# CX AS-IS → людське погодження → BPMN

Навчальний прототип для процесної аналітикині: з інтерв'ю та інших матеріалів кейсу складається опис
процесу «як є» (AS-IS), людина його перевіряє й **погоджує конкретну незмінну версію**, і лише після цього
окремий агентний етап веде до схеми BPMN.

Два агентні етапи, між ними — людина. Агент не погоджує сам себе; усі блокування реалізовані
в програмній логіці сервера, а не в кнопці чи тексті інструкції.

> **Стан на 03.10.2026.** Застосунок працює наскрізь: від додавання джерел до побудованої й перевіреної
> схеми. Платні запуски моделі виконувались і задокументовані (див. «Що доведено справжніми запусками»).
> Проєкт — навчальний прототип, а не продукт для роботи з реальними даними клієнтів.

## Що вміє застосунок

| Етап | Що відбувається | Хто вирішує |
|---|---|---|
| Джерела | інтерв'ю, запити, документи, нотатки; текстом або файлом; походження «синтетичне / реальні дані» вказує людина | людина |
| Аналіз (агент 1) | складає або **частково оновлює** опис AS-IS за доданими джерелами; розрізняє факт джерела, гіпотезу, невідоме й пропозицію | агент пропонує |
| Перегляд і уточнення | кроки, межі, твердження з цитатами, питання, проблеми; редагування створює **нову версію**, попередні лишаються | людина |
| Погодження | прив'язане до версії та її хеша; зміна опису скасовує погодження | **лише людина** |
| Смислова перевірка (агент 2) | шукає неоднозначності в погодженому описі й формує **таблицю процесу** (CSV) | агент пропонує, рішення за знахідками — людина |
| Перевірка таблиці | програма звіряє кожен рядок таблиці саме з погодженим описом | програма |
| Побудова | скрипти пайплайна (`pipeline/`, Python + Node) будують `.bpmn` і `.drawio` | програма |
| Звірка файлів | готові файли перевіряються проти опису й допустимого стилю `.drawio` | програма |
| Перегляд і завантаження | схема в bpmn-js, завантаження `.bpmn`, `.drawio` і таблиці `.csv` | людина |

Окремо реалізовано: бюджет і журнал платних запусків, повторне використання рішень людини між версіями,
погоджений короткий підпис початкової події, захист від застарілого результату, збереження незавершеного
введення при автооновленні.

## Архітектура

- **Без збірки.** Node.js 22 + TypeScript через `tsx`; база — вбудована `node:sqlite`; перевірка даних — `zod`.
- **Сервер** (`src/`) тримає всі правила: версії та їхні хеші, погодження, блокери, шлюз до побудови.
  Браузер нічого не вирішує.
- **Інтерфейс** (`public/`) — звичайний JavaScript без фреймворку, п'ять вкладок: Огляд · AS-IS · Джерела ·
  Схема · Історія.
- **Побудова схеми — не наш генератор.** Схему будує ланцюг скриптів власниці (`pipeline/`, робоча копія
  оригіналів із `reference/bpmn-pipeline/original/`) з таблиці процесу, яку формує агент 2. Програма таблицю
  **лише перевіряє**, запускає скрипти й звіряє готові файли. Прихованого запасного генератора немає — за цим
  стежить тест (`tests/no-csv-generator.test.ts`).
- **Потрібен Python 3** для побудови схеми (шлях можна задати змінною `CX_PYTHON`).

Контракти: `docs/csv-contract.md` (таблиця процесу), `docs/agent1-delta-contract.md` (часткове оновлення
опису), `prompts/analyst.md` (агент 1), `prompts/bpmn.md` (агент 2), `pipeline/DIFFERENCES.md` (відмінності
робочої копії від оригіналів).

## Встановлення й запуск

```bash
npm install            # Node.js ≥ 22.13 (потрібна вбудована node:sqlite)
npm run demo           # демонстраційний кейс, БЕЗ викликів моделі
npm start              # звичайний запуск
```

Застосунок слухає `localhost`; у консолі друкується готове посилання для входу разом із кодом доступу.

- **Windows, крок за кроком:** `docs/windows-start.md`; оновлення зі збереженням даних — `docs/windows-update.md`.
- **Підключення справжньої моделі, ключ і бюджет:** `docs/model-setup.md`. Без повного набору змінних
  (`ANTHROPIC_API_KEY`, `MODEL_MODE=real`, `CX_MODEL`, `CX_BUDGET_USD_TOTAL`) застосунок **відмовляє
  зі списком, чого бракує**, і мовчки не переходить у деморежим.
- **Як пройти продуктовий сценарій самостійно:** `docs/demo-guide.md`.
- **Експорт одного кейсу для розбору якості:** `docs/export-case.md`.

## Перевірка

```bash
npm test                                            # 828 тестів
npx tsc --noEmit                                    # типізація
node --import tsx scripts/verify-key-path.ts        # ключовий шлях цілком + три блокування
node --import tsx scripts/verify-product-route.ts   # маршрут користувача у двох процесах
node --import tsx scripts/verify-ui-defects.ts      # дефекти інтеграції інтерфейсу (D98)
node --import tsx scripts/verify-ui-drafts.ts       # збереження незавершеного введення (D99)
node --import tsx scripts/verify-readability.ts     # читабельність на довгих текстах (D100, D101)
node --import tsx scripts/verify-v29-navigation.ts  # навігація широкою схемою на збереженій таблиці v29
```

Усі перевірки створюють **окремі тимчасові бази** й використовують **підставні клієнти** агентів: мережі,
ключів і платних викликів у них немає. Останні результати — у розділі «Перевірено» в `docs/handoff.md`.

## Що доведено справжніми запусками, а що — ні

- **Справжні платні запуски були** і задокументовані: контрольний прогін агента 1
  (`docs/control-run-v05-report.md`, $0,904472), перший запуск часткового оновлення (D81, $0,50398, відповідь
  **відхилена програмною перевіркою**), запуск агента 2 (D89, $0,30824, завершився помилкою через розбіжність
  ID в інструкції та валідаторі — виправлено, додано тест узгодженості).
- **Доведено програмою:** увесь ланцюг перевірок і блокувань, побудова схеми справжніми скриптами пайплайна,
  поведінка інтерфейсу.
- **Не доведено:** стабільна **якість** висновків агентів. Критерії (`evals/cx-preparation/`) вимагають двох
  незалежних прогонів; їх не виконано. Файли експортів кейсів у репозиторії не зберігаються.

## Межі й обмеження

- Навчальний прототип: постійного розміщення немає, застосунок працює локально.
- Матеріали з позначкою «реальні дані» моделі **не надсилаються**; кейси не публікуються.
- Деморежим завжди позначений у заголовку й ніколи не підміняє справжню модель мовчки.
- Windows-інструкції написані, але **на Windows не перевірялись** (розробка велась у Linux).
- Схему можна побудувати лише для того, що вміє нотація v1; підтверджена вимога до складнішої нотації
  зупиняє побудову з поясненням, а не спрощує схему.
