## Умови прогону (щоб порівняння було чесним)
- Ті самі джерела й порядок етапів сценарію А; модель і режим (`text_json`) ті самі; нова база/кейс. Одного прогону недостатньо, щоб говорити про «покращення»: модель недетермінована. План: **два незалежні прогони** етапів 1–2 (≈ $0,9 кожен за фактом v0.4; ліміт на запуск $1,5 лишається), результати показувати поруч, а не усереднювати.
- До прогону не змінювати цей файл. Якщо критерій виявиться хибним, правка — окремим коммітом із причиною, а прогін повторюється.

## А. Програмні критерії (скрипт; кожен — окремо, без «середнього»)
| № | Критерій | Ціль |
|---|---|---|
| A1 | Суперечності (`CONTRADICTION`) у версіях агента | 0 |
| A2 | Агент змінив початок | 0 (початок задає аналітикиня) |
| A3 | Недосяжні кроки, створені агентом, за початку, заданого аналітикинею | 0 (або кожен — з невідомим переходом і питанням) |
| A4 | Єдиний перехід з умовою (`SINGLE_CONDITIONAL_BRANCH`) | 0 |
| A5 | Найдовша назва дії | ≤ 160 символів; медіана ≤ 100 |
| A6 | Посилання «Q…» у тексті кроків | 0 |
| A7 | Пропозицій вимог до нотації за етап | ≤ 2, кожна з поясненням у `detail` (див. B6) |
| A8 | Спроб на етап | ≤ 2; причини невдалої спроби **збережено** в журналі (`checks.failed_attempts`) |
| A9 | Вартість етапу | ≤ $1,0 (ліміт на запуск $1,5) |
| A10 | Питань про межі (тригер, початок, завершення, склад меж), закритих агентом | 0 |

Примітка: якщо A1/A4/A6 порушено, програма повторює запуск (D68); тому метрика A8 (скільки спроб і чому) і є прямим показником, чи інструкція v0.5 уникає цих порушень, а не лише чи їх «відсіяла» перевірка.

## Б. Змістові критерії (людина; кожен — так / ні / частково + цитата доказу)
| № | Критерій |
|---|---|
| B1 | Крок, що описує **іншу дію чи іншого виконавця**, не пропонується до заміни/вилучення як «помилковий»: розбіжність між словами різних співрозмовників оформлено питанням або твердженням |
| B2 | Межі (тригер, початок, завершення) записано **з атрибуцією** («за словами…») і лишено питанням, а не закрито висновком агента |
| B3 | Гіпотези: кожна — одна перевірювана властивість; складені розділено; докази стосуються саме цієї властивості (**тривалість підготовки не використано як доказ строку надходження інформації**) |
| B4 | Шари: слова співрозмовника (`source_fact` + `scope` з атрибуцією), висновок агента (гіпотеза/твердження), встановлений факт (лише людина) — не змішано; одиничний випадок з розповіді не став маршрутом |
| B5 | У результатах і діях немає домислів, яких не було в джерелі («іноді може…»); невизначеність лише в питаннях |
| B6 | Пропозиції нотації (якщо є): джерело описує структурну властивість; `detail` пояснює, який зміст неможливо передати простою схемою. Згадка листування, документа чи каналів — не підстава |
| B7 | Види прив'язки питань обрано доречно: «що буде, якщо…» — `exception`; сумнів у порядку кроків — `unconfirmed_sequence`; `direction` лише для справді невідомого переходу |
| B8 | Відома гілка співіснує з невідомою альтернативою без вигаданої завершеності |
| B9 | `summary` — кілька речень; деталі, приклади й канали доступні окремо без втрати змісту (в `details` чи твердженнях) |
| B10 | Етап 1 → етап 2: відповідь на питання етапу 1 не з'явилась у новому джерелі — питання лишається відкритим; нові джерела не стирають правок аналітикині |

## Правила висновку
- «Покращено» можна казати лише коли A1–A4, A6, A10 = 0 у **обох** прогонах і B1–B3 виконано в обох; інакше — «частково» з переліком порушень.
- Кожне порушення A* називається: яка перевірка його спіймала (повтор чи ні) і скільки це коштувало.
- Усі зміни критеріїв після прогону — окремо, з причиною; старі результати лишаються.
