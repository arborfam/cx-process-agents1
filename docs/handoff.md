Побічно: пошкоджений запис займав «слот» рішення — тепер людина отримує зрозуміле пояснення (`RESOLUTION_DAMAGED`), а не помилку бази. **Межа захисту:** контрольна сума виявляє порушення цілісності, але не захищає від того, хто може довільно переписати базу й узгоджено перерахувати суми; підписів свідомо не додано.

- Не просити ключ у чат; не друкувати секретів. Модель, бюджет і ключ погоджено (D63), але **це не доручення на виклики**: платні запуски — лише за явною вказівкою власниці.
- Зріз 3b — лише за новим дорученням. **Не додавати в інтерфейс чи API обхід обов'язкової смислової перевірки** (тест `bpmn-isolation` це охороняє: `src/` поза `src/bpmn/` не імпортує генератор). Не змінювати користувацьку `data`, кейси, погодження, оригінали `reference/bpmn-pipeline/original/`.
- Не активувати hooks без перевірки. PR не створювати без прохання. Пушити лише в `claude/peaceful-allen-f4yf0n`.
- Не послаблювати тести й критерії; зміни правил — явно, з причиною. Не публікувати кейси, не надсилати їх зовні; джерела з позначкою «реальні» моделі не надсилаються (D18). Тестові результати без AI позначати явно.
- Зовнішні перевірки завантажених ZIP виконував **Codex у ChatGPT**, окремо від Claude Code; власниця передає архіви й результати (за її повідомленням). Не приписувати Codex перевірок, для яких немає конкретного повідомлення чи результату. Читабельність p01-sequence і p02-branch **особисто підтвердила власниця**.
- Кінцеві коміти — з рядками `Co-Authored-By: …` та `Claude-Session: …` згідно з налаштуванням сесії; ідентифікатор моделі в артефактах репозиторію не вказувати.
