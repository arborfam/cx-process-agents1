# UX/UI-специфікація: AS-IS аналіз → BPMN

Версія 0.1 · 03.10.2026 · **Пропозиція дизайну.** Не реалізовано в продукті.
Основа: коміт `3e9e5e3`, гілка `claude/peaceful-allen-f4yf0n`.
Архітектура не змінюється: агент 2 → CSV → програмні перевірки → наявний Python/Node-пайплайн → BPMN і drawio → перевірка результату.

---

## 1. Для кого і що змінюється по суті

Користувачка — процесна аналітикиня. Вона не повинна:
діагностувати збої, переносити журнали між агентами, пояснювати в зовнішньому чаті, що сталося,
повторювати вже ухвалене рішення після кожної перевірки, відкривати PowerShell для звичайного відновлення.

Чотири речі, які прибирає цей дизайн:

1. **Зайві підтвердження.** Службового «передати на погодження» для одного користувача немає.
   Редакційні правки окремого підтвердження не потребують. Лишається одне змістовне «Погодити версію».
2. **Повторне введення.** Рішення зберігається з предметом, поясненням, автором, датою, доказами й контекстом;
   перед повторним використанням перевіряється його **змістова** актуальність, а не збіг тексту чи ID.
3. **Непрозорі збої.** Кожен збій називає причину людською мовою, що збережено, що не прийнято,
   що відомо про витрати й наступну безпечну дію.
4. **Ручну послідовність.** Пакет джерел → **одне** оновлення. Пакет пов’язаних змін → **одна** операція.

## 2. Структура

```
Шапка: назва процесу · статус · версія
Вкладки: Огляд · AS-IS · Джерела · Схема · Історія
  AS-IS (тихіша внутрішня навігація):
    Бізнес-контекст і межі · Кроки · Твердження й докази · Питання · Проблеми й гіпотези
```

- Бізнес-контекст — **перший** змістовий блок огляду і **перша** вкладка AS-IS.
- Окремої вкладки «Редагувати» немає: кнопка редагування стоїть біля відповідного змісту
  (поле контексту, крок у бічній панелі).
- Технічна діагностика — у згорнутому блоці `details`. Хеші, ID, контракти, версії інструкцій і журнали
  не займають основного робочого простору.
- Постійної лівої панелі немає.

### Сітка

| Екран | Поведінка |
|---|---|
| ≥ 1081 px | Огляд до 1200 px, зовнішні відступи 32 px. Основна колонка + права колонка 320 px («Наступна дія», «Потребує уваги»). |
| ≤ 1080 px | Одна колонка. Права колонка піднімається **одразу після короткого контексту**, перед довгим змістом. |
| ≤ 760 px | Відступи 16 px, назва процесу 24 px, «було → стало» в один стовпчик, бічна панель на всю ширину. |
| Схема | Використовує всю доступну ширину (`page.wide`). |

## 3. Огляд і наступна дія

Огляд відповідає на шість питань без прокручування:

| Блок | Що показує |
|---|---|
| Що і навіщо досліджуємо | **Мета процесу** й **мета дослідження** — окремі рядки, їх не зводять. Початок, фактичне завершення, результат, ролі, поза межами. |
| Поточний стан і версія | У шапці: статус, номер версії, позначка «Синтетичний приклад», час погодження. |
| Потребує уваги | Список із типом (текстова позначка), кількістю й прямим переходом. |
| Наступна дія | **Одна** основна дія + причина. За потреби — що саме блокується. |
| Головні зміни | Додано / вилучено / змінено («було → стало») / суперечить / потребує рішення. |

**«Ще не з’ясовано» — допустимий стан**, показується жовтою текстовою позначкою, а не помилкою.
Заповнювати всі поля до початку дослідження не потрібно.

**Неактивної кнопки без пояснення немає.** Якщо побудова недоступна через критичне питання,
головна доступна дія веде **до цього питання**, а блок під нею називає, що блокується і чому.

## 4. Джерела, зміни й докази

- Походження вказує людина явним вибором: **«Робочі матеріали» / «Синтетичний приклад»**. Програма не вгадує.
- Один вибір застосовується **до всього пакета** й зберігається для кожного джерела окремо; будь-яке можна виправити.
- Поки походження не вказано для всіх джерел пакета, кнопка оновлення неактивна — **з поясненням чому**.
- Аналіз **не** запускається після кожного документа: є кнопка «Оновити аналіз одним запуском (N)».

Текстові позначки походження твердження (колір — додаткова, не єдина ознака):

| Позначка | Тип у даних |
|---|---|
| З джерела | `source_fact` |
| Рішення аналітика | `analyst_confirmed` |
| Гіпотеза | `hypothesis` |
| Пропозиція агента | `improvement_proposal` |
| Не з’ясовано | `unknown` |

Твердження джерела **не** стає автоматично перевіреним фактом. Біля кожного твердження з цитатою —
дія «Показати доказ», яка відкриває бічну панель із точним фрагментом; позиція на сторінці зберігається.

Для суттєвої зміни доступні **«було → стало»** (явні підписи, локальне підсвічування), джерело й
окремий рядок **«Наслідок для процесу»**.

## 5. Проблеми й пов’язані рішення

Тип і критичність — **різні** ознаки, показуються окремими позначками.

| Тип | Приклад у прототипі |
|---|---|
| Бізнес-невідоме | Фактичне завершення процесу не з’ясовано (CX, Q1) |
| Суперечність між джерелами | Який ліміт чинний (закупівля, SRC-P02 проти SRC-P05) |
| Рішення, якого очікують від аналітика | Пропозиція об’єднати S6 і S7 |
| Припущення або пропозиція агента | Прибрати цикл доопрацювання (закупівля) |
| Помилка відповіді моделі | — (тип передбачено) |
| Технічний збій | Втрата зв’язку під час побудови |
| Підтверджене обмеження генератора | Тригер 352 символи проти межі підпису 240 (закупівля) |

Кожна проблема показує **що сталося → чому важливо → що блокується → хто має діяти → доступна дія**.

### Пакет пов’язаних змін

Застосування — **узгоджена операція: усе або нічого**. Перед підтвердженням видно:

- які кроки додаються й вилучаються;
- як зміняться переходи;
- які питання й докази втратять прив’язку (питання лишається відкритим, критичність не змінюється);
- що лишиться відкритим після застосування;
- поле **змістовної відповіді** на критичне питання — вона входить у той самий пакет,
  тому редагувати ID вручну не потрібно.

Питання не закриваються автоматично й не знижують критичність самі собою.

## 6. Повторне використання рішень

Рішення про окреме питання і погодження всієї версії — **різні сутності**.
Повторне використання рішення **не** погоджує нову версію.

Зберігається: предмет, пояснення, автор, дата, докази, контекст застосування.
Перевіряється: чи те саме питання; чи не змінилися пов’язані кроки, межі й вимоги; чи не змінилися докази;
чи немає нової суперечності. Самого збігу тексту або ID недостатньо.

Три стани з прямою назвою:

| Стан | Що показано | Дія |
|---|---|---|
| **Рішення чинне — пов’язаний зміст не змінився** | Перелік виконаних перевірок | «Застосувати повторно без змін» |
| **Потрібно переглянути — змінилися …** | Конкретний перелік змін + попереднє пояснення в полі | «Підтвердити пояснення» (можна відредагувати, не вводячи заново) |
| **Попереднє рішення не застосовується** | Що саме змінило підставу + попереднє пояснення як історія | «Записати нове рішення» (обов’язковий текст) |

Відхилення припущення агента не скасовує програмних перевірок і не дозволяє обійти
підтверджене обмеження генератора — це сказано прямо в діалозі.

## 7. Погодження

- Службового «Передати на погодження» для одного користувача **немає**.
- Застосування змістових змін і фінальне погодження — різні дії. Другого загального «Прийняти» немає.
- «Погодити версію» показує **один** змістовний підсумок: точна версія й знімок, межі, суттєві зміни,
  залишкові некритичні питання, короткий підпис події (якщо є).
- У діалозі прямо сказано: погодження прив’язане до незмінного знімка; зміна змісту створює нову версію,
  яка потребує нового погодження; **погодження й платний запуск — окремі рішення**.

---

## 8. Запуски, витрати, відновлення

Три різні речі розрізняються текстом перед дією:

| Вид | Позначка |
|---|---|
| Платне звернення до AI (генерація CSV) | жовта «Платний етап: звернення до моделі» |
| Програмна побудова зі збереженого перевіреного CSV | зелена «Безкоштовно: модель не викликається» |
| Оновлення стану | без позначки витрат |

Перед платним зверненням виконуються всі доступні програмні перевірки, і про це сказано.

**Тривала операція** показує: автооновлення, час від початку, відомий етап, час останнього отриманого стану,
пояснення затримки — **без вигаданого відсотка**. Перелік етапів показує, де саме операція зараз.

**Втрата актуального зв’язку** — окремий стан, не помилка:
«Оновлення стану не надходять NN:NN. Це не доводить, що операція зупинилась». Є ручне оновлення.
Повторне натискання дубля запуску не створює.

**Помилка** лишається доступною й пояснює причину людською мовою, що збережено, що не прийнято,
що відомо про витрати, наступну безпечну дію. Безкоштовна технічна повторна спроба пропонується
**лише** коли є збережений придатний результат і підтверджено, що модель не викликається повторно.
Коли потрібне виправлення розробником — це сказано прямо, разом із готовим діагностичним звітом.

## 9. Схема

- Велике біле полотно, нейтральні елементи, синій акцент вибраного.
- Є: масштабування (кнопки й колесо), переміщення (перетягування), повний екран,
  «Показати всю схему», «Робочий масштаб 100 %», перехід до кроку, деталі вибраного елемента,
  завантаження `.bpmn` і `.drawio` **з видимою версією**.
- Короткі підписи не спотворюють зміст: повний текст тригера показується поруч зі схемою дослівно.
- Ліцензійний водяний знак лишається видимим і не перекривається.
- Відомі вади наявного пайплайна (порожня смуга доріжки, надмірна ширина) названі **окремим блоком вимог**,
  а не замасковані автоматичним зменшенням масштабу.
- Історична схема має явну позначку: версія схеми, чинна версія опису, причина неактуальності;
  завантаження історичного результату теж позначається версією.

Шрифт: `system-ui, -apple-system, "Segoe UI", sans-serif`. Зовнішнього сервісу шрифтів немає.
Назва процесу 28 px напівжирна · заголовок розділу 20 px · заголовок блоку 16 px напівжирний ·
основний текст 16 px / 1.5 · допоміжний 14 px. Моноширинний — лише в діагностиці.

Відступи 4 / 8 / 12 / 16 / 24 / 32. Картки: 20–24 px, радіус 10. Кнопки й поля: радіус 8, висота 44.
Тіні — лише для бічної панелі й діалогів. Картки не вкладаються одна в одну; групування — відстанями й заголовками.
Одна синя кнопка в поточному завданні; решта — нейтральні або текстові.
Основні вкладки — текст і синє підкреслення активної, в один рядок із горизонтальним прокручуванням при потребі.
Внутрішня навігація AS-IS візуально тихіша (пігулки).
Статуси завжди мають текст; колір — додаткова ознака.
Градієнтів, скляних ефектів, декоративних ілюстрацій, емодзі як іконок і великих кольорових банерів немає.
Темну тему відкладено свідомо.
