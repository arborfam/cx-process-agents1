# План зрізу 3b: агент 2, рішення аналітика, генерація, перегляд, захист

Стан (01.10.2026): **3b-1 реалізовано** (без API; D64, `docs/review-3b-1.md`); 3b-2…3b-7 — не починалися. Основа: `docs/technical-plan.md` §1в і §10, рішення D21, D26–D32, D58, D61–D63, `prompts/bpmn.md` (чернетка v0.2, не активна). Платних викликів цей план не потребує й не дозволяє (D63: бюджет погоджено, але виклики — лише за окремою вказівкою).

## Що вже є (на що спираємось)
- Кодовий конвеєр без моделі (зріз 3a): `generate` → зворотна перевірка → `.drawio` зі звіркою → карта «крок ↔ елемент»; статуси `ok / blocked / unsupported / verification_failed`.
- `bpmnGuard` — серверний дозвіл (хеш, погодження, критичні питання, потік, нотація, назва процесу); `requestBpmnStart` зараз лише записує запуск зі станом `not_implemented`.
- `packageFromApproval` — читання погодженого пакета; свідомо **не підключений** до сервера (тест `bpmn-isolation`).
- Модельний шар агента 1: клієнт, перевірка цитат, бюджет із резервом, журнал запусків, повтор. Його перевикористовуємо, а не пишемо знову.

## Принцип порядку
Модель виконує **тільки** смислову перевірку. Усе інше — код. Продуктового шляху «без смислової перевірки» **немає** (D32). Побудова файлу починається лише після успішно завершеної перевірки агента 2 і повторної перевірки `bpmnGuard`.

## Підкроки (кожен — окрема мала зміна, коміт, тести, зупинка на звіт)

**3b-1. Контракт агента 2 (без запуску). ✔ Реалізовано 01.10.2026 (D64).**
- Узгодити й зафіксувати схему відповіді (знахідка: код, `step_ids`, цитата, одне питання, клас, варіанти) і активувати `prompts/bpmn.md` як v0.3 з маркерами runtime.
- Перевірка відповіді кодом: суворий набір полів (поле `action`/`role`/`condition` → відхилити), існуючі `step_ids`, цитата дослівно є в пакеті, одне питання, відомий код знахідки.
- *Тести:* підставний клієнт; негативні відповіді (вигадана цитата, чужий крок, зайве поле, текст для схеми).

**3b-2. Запуск агента 2 (оркестрація).**
- Стани запуску: у черзі → виконується → **очікує рішення аналітика** → готово / `unsupported` / помилка. Заміна `not_implemented`.
- Порядок: `bpmnGuard` → код-перевірки й підказки → виклик моделі → перевірка відповіді → рішення за знахідками. Підтверджена вимога нотації → `unsupported` **без виклику моделі** (D61).
- Деморежим: запуск зупиняється з повідомленням «потрібна модель»; агент 2 не імітується (D32).
- *Тести:* немає виклику моделі при `unsupported`; немає шляху до генерації без завершеної перевірки (структурний тест на кшталт `bpmn-isolation`).

**3b-3. Рішення аналітика (D31).**
- Нова таблиця `finding_resolution` (міграція, старі дані не чіпаємо): копія знахідки, рішення «відхилено», **обов'язкове пояснення**, хто, коли, ID запуску й погодження, хеш пакета. Незмінний запис.
- Для кожної `blocks_flow`: «уточнити AS-IS» (нова версія → нове погодження → новий запуск) або «відхилити з поясненням». `UNSUPPORTED_CANDIDATE` відхилити не можна. Лише людина.
- «Продовжити» перевиконує кодові кроки для того ж пакета **без нового виклику моделі**; кодові перевірки не обходяться.
- *Тести (з плану §10):* відхилення без пояснення не записується; агент не може відхиляти; після відхилення блокують підміна хеша, невизначений перехід, відсутній початковий крок, невдала зворотна перевірка.

**3b-4. Генерація й збереження результату.**
- Після завершеної перевірки: `packageFromApproval` → генератор → результат зберігається як **артефакт, прив'язаний до версії, хеша й погодження** (`.bpmn`, `.drawio`, карта, статус, хеші файлів).
- `verification_failed` / `blocked` / `unsupported` → файл **не створюється й не видається**; погодження AS-IS лишається чинним (D21, D58).
- *Тести:* артефакт має точні `version_id` + `content_hash`; збій запису в базу не лишає напівартефакту; у шляху генерації немає викликів моделі.

**3b-5. Перегляд і завантаження.**
- Вкладка «Схема» на картці: перегляд `.bpmn` (переглядач bpmn-js, водяний знак лишається, D30), таблиця «крок ↔ елемент», **явне попередження**, що технічна перевірка не доводить змістову правильність; завантаження `.bpmn` і `.drawio`.
- Завантаження — лише для чинного артефакту (див. 3b-6); перевіряється хеш файлу перед видачею. Застарілий артефакт у історії позначено «Застаріла — побудована за версією …»; для нової версії AS-IS він не приймається (D65).
- bpmn-js переходить із `devDependencies` у залежності виконання й віддається з `public/` (рішення D65); оновити `THIRD_PARTY_LICENSES.md`, водяний знак лишається.

**3b-6. Захист від застарілої версії.**
- Артефакт чинний лише поки `bpmnGuard` проходить для **тієї самої** версії й хеша. Нове джерело, нова версія, скасоване погодження → артефакт позначається «Застаріла — побудована за версією …» (D65): лишається в історії, **як чинний не показується й не завантажується, для нової версії AS-IS не приймається**; історія не стирається.
- Перевірка на трьох рівнях: перед запуском, перед збереженням результату (у транзакції), перед завантаженням.
- Результат запуску, що завершився після появи нової версії, зберігається як застарілий, не як чинний (за аналогією з D39).
- *Тести:* погодження старої версії; нове джерело після побудови; скасування погодження під час запуску; підміна хеша; прямий HTTP-запит без сесії/дозволу.

**3b-7. Збої.**
- Модель недоступна, тайм-аут, відповідь не за схемою → одна автоматична повторна спроба для тимчасового збою; далі запуск `error`, артефакту немає, стан кейсу й погодження без змін; ручний повтор — новий запуск із `retry_of` (D32). Бюджет: резерв і невідома вартість — як у D45–D46.
- Перезапуск сервера під час запуску → запуск `error`, не «вічно виконується».
- Збій генератора/зворотної перевірки → зрозуміле пояснення, файлу немає; `.bpmn` чинний, якщо збій лише в `.drawio` (D60).
- *Тести:* кожен збій окремо; стан кейсу до й після однаковий.

### Зміни плану за результатами 3b-1 (реальність не збіглася з планом)
- Шлюз до генерації (`generationGate`) з'явився вже в 3b-1, а не в 3b-2: без нього неможливо довести, що збій чи некоректна відповідь не відкривають генерацію. Рецензент знайшов, що початковий шлюз можна було відкрити мутацією результату, демо-клієнтом і підміною змісту — додано глибоке заморожування, заборону `demo`, відбиток змісту й звірку версії інструкції.
- У 3b-2 **шлюз має викликатися перед кожною генерацією** і повторно перед збереженням артефакту; у продуктовому шляху не має бути іншої гілки до генератора (структурний тест, як `bpmn-isolation`).
- У 3b-3: попередження про цитати (скорочення «…», нормалізація, цитата поза вказаними кроками) мають бути **видимі в картці знахідки**; `question` і `options` — текст для аналітика, **ніколи не підставляється в AS-IS автоматично**.
- Пороги цитати (≥ 10 символів; ≤ 4 частин по ≥ 5) — припущення; перевірити на справжній моделі, коли доступ відновиться, і міняти лише явним рішенням.
- Справжній клієнт агента 2 (`AnthropicBpmnClient`), облік бюджету й журнал запусків — 3b-2; `reviewJsonSchema` приймання API не перевірено.

## Критерії завершення 3b (перевіряються тестами та оглядом)
1. Без завершеної смислової перевірки файл не створюється (структурний тест + прямий запит).
2. `blocks_flow` зупиняє запуск до рішення; відхилення з поясненням записується й видно в історії; кодові блокування діють після відхилення.
3. `unsupported` не змінює AS-IS і не викликає модель, коли вимога підтверджена.
4. Артефакт прив'язаний до версії й хеша; застарілий не видається як чинний.
5. Збої не псують стан кейсу, погодження й бюджет.
6. Агент 2 не повертає тексту для схеми; відповідь із такими полями відхиляється.
7. `npm test` і `tsc` — без регресій (зараз 398/398); кількість нових тестів і мутаційних перевірок названо у звіті.
8. **Окремо й чесно:** якість смислової перевірки на справжній моделі **не заявляється**, доки немає успішного запуску й оцінки; до того — позначка «перевірено лише на підставних відповідях».

## Що можна робити без API, а що ні
- **Без API:** 3b-1…3b-7 повністю (підставний клієнт у тестах, позначений як такий).
- **Лише з API (за окремою вказівкою):** справжня перевірка якості агента 2 на пакетах `tests/bpmn-fixtures/` і сценарії А; частка хибних спрацьовувань і відхилень (технічний план, ризики 16 і 18). Спершу — відновлення доступу до API (D63), одним найдешевшим запитом.

## Ризики
- Агент 2 може давати хибні знахідки або мовчати про справжні неоднозначності; пом'якшення — цитата перевіряється кодом, рішення людини з поясненням, звірка за таблицею «крок ↔ елемент».
- Відхилення може стати «швидким обходом»; пом'якшення — обов'язкове пояснення, незмінний запис, видимість у підсумковому документі, лічильник відхилень.
- Доступ до API може не відновитись вчасно; тоді 3b завершується «на підставних відповідях» з чесною позначкою, а справжня перевірка лишається окремим кроком.

## Рішення власниці (01.10.2026, D65)
1. 3b-1 почати без API — **виконано**.
2. Застаріла схема: **в історії, з позначкою «Застаріла — побудована за версією …»; не як чинна; не приймається для нової версії AS-IS.**
3. bpmn-js включається в застосунок на підкроці 3b-5; водяний знак зберігається.

Наступні підкроки (3b-2…) — лише за новим дорученням.
