# План hooks

> **Період дії.** Історичний план hooks (29.09.2026). Hooks **не активовані** й не є частиною продукту. Поточний стан — `README.md`.

Стан: активної конфігурації ще немає. Вона залежить від обраного стеку й реальних команд перевірки. Не додавати команди-пустишки, що завжди повертають успіх.

За офіційною документацією станом на 29.09.2026 repository hooks підтримуються в Anthropic-hosted cloud. SessionStart налаштовується в .claude/settings.json; для сесій із кількома репозиторіями repository hooks не завантажуються. Для прототипу — один репозиторій.

| Подія / механізм | Призначення | Коли додати |
|---|---|---|
| SessionStart | Перевірити або підготувати залежності проєкту, без друку секретів | Після вибору стеку й створення lockfile |
| PostToolUse для редагувань | Коротка перевірка формату змінених інструкцій/схем | Коли є справжній валідатор і перевірені події редагування |
| Команда перевірки + CI | Тести переходів, версій, формату даних | У першому програмному зрізі |
| Stop | Поки не використовувати як нескінченний цикл вимог; за потреби додати обмежену перевірку | Лише після доказу користі |

Hooks Claude Code стосуються розробки; погодження AS-IS контролює backend продукту. Правило у CLAUDE.md є інструкцією, а не гарантованою забороною.

Для кожного доданого hook перевірити: спрацювання на потрібній події, успішний випадок, відомий дефект, тайм-аут, відсутню залежність, зрозуміле повідомлення. Перевірити фактичне завантаження у новій cloud-сесії. Не оголошувати hook активним лише тому, що файл створено. Звичайне тестування має працювати і без hooks.
