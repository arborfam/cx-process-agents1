- **База:** таблиця `bpmn_review` (незмінна, тригери): ID запуску, версія, погодження, хеш, відбиток змісту, версія й хеш інструкції, режим і модель клієнта, прийнята відповідь, знахідки, попередження, облік спроб, висновок (`clear` / `awaiting_analyst` / `unsupported` / `stale`), хеш запису.
- **Клієнт** `src/ai/anthropic-bpmn-client.ts` (справжній; у деморежимі не створюється). Послаблена схема для API без `minLength/maxLength/maxItems` (структурований вивід їх не підтримує; суворі межі перевіряє код). Помилки через спільний `classifyAnthropicError`.
- **Спільне з агентом 1:** `preflight`, `reserveRetry`, `actualCostUsd`, таблиця `run`, `recoverStuckRuns`; бюджет $10 / $1,5 на запуск з повтором; атомарне резервування; невідома вартість лишається в резерві. Оцінка входу враховує схему саме агента 2.
- **Сервер:** `POST /api/cases/:id/bpmn/review` (людина, сесія, захист від підробки запитів; **тіло ігнорується**) і `GET` (читання відновленого стану). Старий `bpmn/start` не змінювався.
- **`src/ai/bpmn-review.ts`:** облік вартості по спробах, хук `beforeAttempt` (резерв повтору), `reissueReview` (відновлення з повторною перевіркою відповіді), `reviewOutcome`.
- **Не додано:** рішення аналітика (3b-3), генерацію й збереження схеми (3b-4), інтерфейс і переглядач (3b-5), застарілі схеми (3b-6), підпис записів.

## Підроблений або змінений запис — що ловиться
Змінене будь-яке поле без перерахунку хеша; перерахований хеш, але знахідки/висновок/відповідь суперечать одне одному або повторній перевірці; вигадана цитата у відповіді; режим, модель, інструкція, погодження чи версія не збігаються з журналом запуску; погодження існує, але для іншої версії; підроблений хеш версії; відбиток змісту; запис без запуску; прямий `INSERT`; запис `unsupported` з іншими вимогами; змінений зміст версії.
**Межа (чесно):** це контроль цілісності, а не підпис. Хто може писати у файл бази й знає формат, здатний створити внутрішньо узгоджений запис (наприклад, порожню відповідь з режимом `real` і правильним хешем). Захист — HMAC із секретом поза базою — окреме рішення, не реалізовано.

## Що пішло не так під час перевірки (не приховуємо)
1. **Перший мутаційний прогін впав, а не завис.** Мутація №23 упиралась у тайм-аут 300 с; мій скрипт не обробив `TimeoutExpired`, завершився з трасуванням, а **таблицю результатів (друкувалась лише в кінці) втрачено**. Лишився сирітський процес тестів — зупинено лише його. Я даремно чекала довше, ніж треба: 22 мутації минули за ~2 хв.
2. **Контрольної копії `src/` перед мутаціями не було** (оригінал тримався в пам'яті скрипта). Після аварії спершу збережено поточні файли й diff (scratchpad), а потім доведено, що поломок немає: для всіх 27 мутацій оригінальний фрагмент присутній у файлі, слідів підміни немає, `tsc` і повний набір зелені. Далі зроблено **контрольну копію з sha256-звіркою** і надійний скрипт: послідовно, тайм-аут 90 с, вбивство лише власної групи процесів, друк після кожної мутації, відновлення з копії, підсумкова звірка файлів.
3. **Надійний прогін показав справжні прогалини тестів:** 7 мутацій не виявлено, одна «зависла».
   - **Зависання** було дефектом самого тесту: у тесті «після перезапуску сервера» перший сервер закривався без `try/finally`, при провалі перевірки він лишався відкритим, і тест-процес не виходив. Виправлено.
   - **№03** (перевірка «запуск завершений» у `checkRecord`) — **мертвий код**: незавершені запуски відсіюються раніше (`getCaseReview`); перевірку видалено.
   - **№04, 05, 06, 09, 18, 24** — шари захисту перекривали один одного (кожен окремо не виявлявся) або не було тесту. Додано цільові тести: відбиток змісту, погодження для іншої версії, узгоджено підроблений хеш версії, підроблений запис `unsupported`, правило D18 для реальних даних, окремий тест `reissueReview`. Повторно: усі виявлено.
4. **Помилка в тестових допоміжних функціях:** параметри за замовчуванням (`policy = policyOf()`, `usage = USAGE`) перехоплювали `undefined` і ховали випробування «без політики» та «без usage». Виправлено явним `null`; тести стали справжніми (перший прогін ловив це, три тести були червоні).
