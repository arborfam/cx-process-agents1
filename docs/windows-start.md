# Запуск демо на Windows: покрокова інструкція

> Демо вже встановлено й запущено? Для оновлення зі збереженням даних див. **docs/windows-update.md**.

Стан: **ДЕМОРЕЖИМ — не AI.** Усі матеріали синтетичні, жодних викликів моделі, дані не залишають ваш комп’ютер. Час: 10–15 хвилин, більшість — установлення.

> **Що перевірено, а що ні.** Я перевіряла застосунок на Linux: типізація й усі 38 тестів проходять на Node.js **22.13.0**, **22.22.2** і **24.21.0**; на 22.12.0 застосунок не працює (немає вбудованої бази) — тому мінімум саме 22.13. **На Windows я не запускала.** Кроки нижче — стандартна поведінка Windows і npm; якщо щось виглядає інакше, надішліть мені точний текст помилки.

## Що потрібно
- Windows 10 або 11, інтернет.
- Обліковий запис GitHub, який має доступ до приватного репозиторію `arborfam/cx-process-agents1`.
- ≈150 МБ місця (на Linux залежності займають 67 МБ).

## Крок 1. Установіть Node.js — версії 22.13 або новішої
1. Відкрийте **https://nodejs.org** → розділ завантаження → **Windows Installer (.msi)**, 64-розрядний (для Windows на ARM — ARM64).
2. Оберіть версію **LTS**. Підійдуть **22.13 і новіші 22.x** та **24.x** (перевірені). Версії 20 і старіші **не підійдуть**.
3. Запустіть установник, залишайте все за замовчуванням («Next» → «Install»). Прапорець «Automatically install the necessary tools» **не потрібен**.
4. **Закрийте всі вікна командного рядка, якщо вони були відкриті**, — вони не побачать нового Node.js.

## Крок 2. Завантажте саме гілку з реалізацією (не `main`!)
Код застосунку є **лише в гілці `claude/peaceful-allen-f4yf0n`**. У гілці `main` — тільки 8 файлів документації; якщо завантажите її, `npm install` не знайде проєкту (я перевірила: `package.json` у `main` немає).

1. Увійдіть у GitHub і відкрийте: **https://github.com/arborfam/cx-process-agents1/tree/claude/peaceful-allen-f4yf0n**
2. Переконайтеся, що зліва вгорі в кнопці гілок написано `claude/peaceful-allen-f4yf0n`, а у списку файлів є **`package.json`** і папки `src`, `public`.
3. Натисніть зелену кнопку **Code → Download ZIP**. Завантажиться файл на кшталт `cx-process-agents1-claude-peaceful-allen-f4yf0n.zip`.
   *(Запасний варіант — пряме посилання, теж потребує входу в GitHub: `https://github.com/arborfam/cx-process-agents1/archive/refs/heads/claude/peaceful-allen-f4yf0n.zip`. Я його не перевіряла, бо репозиторій приватний.)*

## Крок 3. Розпакуйте
1. Створіть папку **`C:\cx-demo`** (не на Робочому столі й не в OneDrive: синхронізація й довгі шляхи заважають).
2. Клацніть завантажений ZIP правою кнопкою → **Витягти все… / Extract All…** → вкажіть `C:\cx-demo` → **Витягти**.
   Не запускайте файли всередині ZIP без розпакування.
3. Відкрийте розпаковану папку (вона матиме назву, схожу на `cx-process-agents1-claude-peaceful-allen-f4yf0n`). **У ній мають лежати `package.json`, `src`, `public`, `docs`.** Якщо всередині є ще одна папка з таким самим іменем — зайдіть у неї.

## Крок 4. Відкрийте Командний рядок у цій папці
1. Перебуваючи у папці, де лежить `package.json`, клацніть у **рядок адреси** Провідника (угорі), видаліть текст, введіть **`cmd`** і натисніть **Enter**.
2. Відкриється чорне вікно, у якому шлях закінчується назвою вашої папки. Перевірте:
   ```
   dir package.json
   ```
   Має з’явитися рядок із `package.json`. Якщо «File Not Found» — ви не в тій папці (див. крок 3.3).

Використовуйте саме **Командний рядок (cmd)**, а не PowerShell: у PowerShell політика безпеки часто блокує `npm` («running scripts is disabled»).

## Крок 5. Перевірте версію й підготуйте кодування
```
chcp 65001
node --version
```
- `chcp 65001` вмикає UTF-8, щоб українські літери в консолі не перетворилися на «???». Виводить «Active code page: 65001».
- `node --version` має показати **v22.13.0 або вище** (наприклад, `v22.22.0`, `v24.x.x`). Якщо «’node’ is not recognized» — закрийте вікно й відкрийте нове (крок 4); якщо не допомогло — перевстановіть Node.js (крок 1).

## Крок 6. Установіть залежності (один раз)
```
npm install
```
Триває 1–3 хвилини. У кінці буде щось на кшталт `added … packages` і, можливо, рядок про «funding» — це нормально. Якщо бачите `EBADENGINE … Required: {"node":">=22.13"}` — у вас застаріла версія Node (крок 1).

## Крок 7. Запустіть демо
```
npm run demo
```
З’явиться блок:
```
══════════════════════════════════════════════════════════════
 ДЕМОРЕЖИМ — не AI. Перевіряється програмна логіка.
 База кейсів: data/cx.sqlite
 Відкрийте в браузері це посилання (скопіюйте весь рядок нижче):

   http://localhost:3000/login?code=…….

 Зупинити: Ctrl+C. …
══════════════════════════════════════════════════════════════
```
**Не закривайте це вікно** — поки воно відкрите, застосунок працює.

## Крок 8. Відкрийте застосунок
1. Виділіть мишею рядок `http://localhost:3000/login?code=…` і натисніть **Enter** (це копіює; поки текст виділено, застосунок на паузі — після Enter він продовжить). Або просто перепишіть посилання.
2. Вставте його в адресний рядок браузера (Chrome, Edge, Firefox).
3. Ви побачите жовту смугу **«ДЕМОРЕЖИМ — не AI»** і список із демо-кейсом «ДЕМО: Зміна умов обслуговування». Код у посиланні — це «вхід людини»: лише з ним можна погоджувати; нікому його не пересилайте.

Далі — сценарій перевірки: **docs/demo-guide.md** (відкриється й у розпакованій папці, `docs\demo-guide.md`).

## Зупинити і запустити знову
- **Зупинити:** у вікні cmd натисніть **Ctrl+C**; якщо спитає «Terminate batch job (Y/N)?» — введіть **Y** і Enter.
- **Запустити знову:** відкрийте cmd у тій самій папці (крок 4), виконайте `chcp 65001` і `npm run demo`. Повторно `npm install` не потрібен. Ваші кейси й версії лишаються: вони у файлі `data\cx.sqlite`.
- **Почати з чистого аркуша:** зупиніть застосунок і видаліть папку `data` у проєкті.
- **Отримати нову версію коду:** завантажте ZIP гілки ще раз у **нову** папку (кроки 2–3), скопіюйте в неї стару папку `data`, якщо хочете зберегти кейси. Демо-кейс зі старим змістом сам не оновиться: для нового змісту видаліть `data`.

## Якщо щось пішло не так
| Що бачите | Причина і що робити |
|---|---|
| `’node’ is not recognized…` | Node.js не встановлено або cmd відкрито до установлення. Закрийте й відкрийте cmd заново; інакше перевстановіть Node.js |
| `npm error code EBADENGINE` | Версія Node старіша за 22.13. Встановіть новішу (крок 1) |
| `npm : File … cannot be loaded because running scripts is disabled` | Ви у PowerShell. Використайте cmd (крок 4) |
| `npm error ETIMEDOUT / ECONNRESET / SELF_SIGNED_CERT…` | Мережа блокує реєстр npm (VPN, корпоративний проксі, антивірус). Спробуйте іншу мережу; або надішліть мені текст помилки |
| `Cannot find module` / `package.json not found` | Ви не в тій папці (перевірте `dir package.json`) або завантажили `main` замість гілки (крок 2) |
| `EADDRINUSE … 3000` | Порт зайнятий. Виконайте `set PORT=3001`, потім `npm run demo`; посилання буде з `:3001` |
| Вікно брандмауера Windows про Node.js | Застосунок слухає лише на цьому комп’ютері (`127.0.0.1`), доступ із мережі не потрібен. Якщо запитає — можна натиснути «Скасувати/Cancel»; локально все працюватиме |
| Браузер: «Потрібен вхід» | Відкрито `http://localhost:3000` без коду. Використайте повний рядок із консолі (код також у `data\access-code.txt`) |
| У консолі «??????» замість літер | Не виконано `chcp 65001`. На роботу у браузері це не впливає |
| Після оновлення коду сторінка виглядає по-старому | Натисніть **Ctrl+F5** |

## Необов’язкова самоперевірка (≈10 секунд)
```
npm test
```
Очікуваний підсумок: **`tests 38`, `pass 38`, `fail 0`** (рядки починаються з `# ` або `ℹ `). Я не запускала тести на Windows: якщо вони впадуть у вас, а застосунок працює, це не обов’язково дефект — надішліть мені вивід.
