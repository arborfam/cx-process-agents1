# Звіт: зріз 3a — генерація та перевірка BPMN без моделі (01.10.2026)

**Головне:** генератор, зворотна перевірка й експорт `.drawio` реалізовано та перевірено на вручну підготовлених синтетичних пакетах. **Жодного виклику моделі, ключ не запитувався, платного нічого не було. Усе створене тут — без AI.** Генератор **не підключено** до сервера, API й інтерфейсу; обходу смислової перевірки не створено. Зріз 3b не починався. Зріз 2 за якістю AI не вважається прийнятим (перший справжній аналіз заблоковано відмовою API про баланс; діагностика відкладена).

## 1. Що реалізовано (`src/bpmn/`, рішення D49–D59)
| Вимога | Як |
|---|---|
| Генератор на TypeScript | перевірка входу → побудова → розкладка → зворотна перевірка → експорт; чиста функція, у пам'яті, без файлів і спільного стану; унікальні ID за конструкцією (перевіряються наприкінці); екранування атрибутів, переносів рядка |
| Лейаутер | `bpmn-auto-layout@2.0.0-alpha.2` (прибита версія, MIT) + власна постобробка: задачі збільшуються під найдовший підпис (лейаутер ігнорує розміри й завжди малює 100×80), підписи умов лишаються поруч зі своїми лініями, лінії, що збіглися б, розводяться |
| Початок | лише `entry_step_id`; порядок кроків не має значення (тест: усі перестановки → побайтово той самий файл) |
| Дослівність | дії, ролі, умови, тригер, назва пулу; нейтральна `task` (без іконки «людина»), початок і кінці без типу, шлюзи й кінці без назв |
| Основний результат `.bpmn` | незалежний читач зі **суворим XML-розбором** розбирає готовий файл назад і звіряє: дії, ролі, умови, переходи, цикли, початок, версію й хеш, зайву нотацію, досяжність, геометрію |
| `.drawio` | експорт із ID кроків у клітинках, власна звірка (підписи, ролі, переходи за самим `.drawio`, кількість стрілок, геометрія, зайві маркери/символи); провал звірки не скасовує чинний `.bpmn` |
| `unsupported` (D21) | пояснення: які кроки, який елемент, чому, що без відображення, що погодження не змінено, варіанти; файлу немає |
| K1/K2 (D28) | K1 блокує, K2 не блокує й показується як «відомі обмеження» |
| Перегляд і карта | `docs/bpmn-3a/`: HTML-переглядач із водяним знаком bpmn.io, карта «крок ↔ елемент» (клікабельна), знімки |
| Документація | виправлено формулювання про негативні приклади (лапки й кілька умов в одну ціль — коректні входи): `docs/technical-plan.md` §10, зріз 3a, п. 8 |

## 2. Що фактично перевірено
- `npm test`: **297 із 297** (було 114; +183 нових), 0 пропущено; `tsc --noEmit` чистий.
- **Позитивні** (11 пакетів із очікуванням, записаним у пакеті до запуску): послідовність, розгалуження, цикл із виходом, початок не в першому рядку, кирилиця, лапки й спецсимволи, довгі підписи, перенос рядка, різні умови в одну ціль, K2, `unsupported`, K1.
- **Входи, що відхиляються (30):** повторні ID, неіснуючі посилання, недосяжний крок, замкнений цикл, відсутній/хибний початок, «невідомо», `[TO DEFINE]`, керівні символи/табуляція/каретка, зарезервований і хибний ID, порожні тексти, невідома/повторна роль, єдина умовна гілка, умови без підписів/дублі/неоднозначні, критичне питання, відкрита пропозиція, хибна прив'язка до версії, надто довгий підпис (`unsupported`).
- **Входи, що зберігаються без втрат:** лапки і спецсимволи в усіх полях; кілька різних умов в одну ціль (6 виходів з одного кроку); K2.
- **Пошкодження готового файлу (≈60 для `.bpmn`, 20 для `.drawio`):** доданий/втрачений крок, змінена дія чи умова, неправильна доріжка, втрачений перехід і цикл, зайвий таймер/паралельний шлюз/userTask/примітка/підпроцес, зіпсований XML, дубль ID, відсутня й нечислова геометрія, накладання, блок поза доріжкою, обрізаний підпис, відірвана й вироджена стрілка, лінії, що збіглися, застаріла версія/інший хеш. Кожна мутація перевіряється на те, що вона **справді змінила файл**. Окремо: пошкоджений результат не видається (`verification_failed`).
- **Ізоляція:** 24 пари (48 процесів) одночасно в одному процесі Node **і** 48 окремих процесів ОС одночасно: кожен результат збігається зі своїм пакетом, не збігається з чужим і побайтово дорівнює послідовному запуску. У шляху генерації немає моделі, мережі, файлів, `process.env`, випадковості, змінного стану модуля (статичний тест).
- **Порівняння з оригінальним Python-ланцюгом** (запускався з тимчасової теки, оригіналів не змінено — контрольні суми в тесті): на 6 коректних пакетах зміст і структура збігаються після нормалізації (`docs/decisions.md` D59). Дефекти оригіналу **не відтворено**: повторні ID ліній, лапка в назві (оригінал каже «OK» і дає зіпсований XML), глобальний стан доріжок.
- **Мутаційна перевірка самого коду:** 16 навмисних поломок генератора/читача (умови не на лініях, початок = перший рядок, вимкнена звірка дії/хеша, лінії-дублікати не розводяться, дозволена єдина умовна гілка/«невідомо»/табуляція, не екранується лапка, видача файлу попри помилки, експорт без звірки, накладання як попередження, схема не збільшується, усі задачі в першій доріжці, порядок рядків впливає на схему) — **усі 16 виявлені тестами**. Одна («невідомо») спершу виявилась «невиявленою» через мою помилку в мутації (вимкнена лише дублююча гілка); виправлено, виявлено.
- **Візуально (знімки переглянуто):** `.bpmn` — у `bpmn-js` 18.30.1 (Chromium), водяний знак на місці; `.drawio` — в офіційному переглядачі draw.io (`viewer-static`).
- **Масштаб:** 30/60/120 кроків → `ok` за 0,2/0,4/0,7 с, без попереджень.

## 3. Дефекти, знайдені й виправлені під час роботи (чесно)
1. **Дві умови в одну ціль малювалися однією лінією** (одну стрілку не видно) — виявлено на знімку; тепер лінії розводяться, а збіг ліній — помилка перевірки (`EDGE_HIDDEN`).
2. Лейаутер записує **табуляцію «сирою»** — вона тихо ставала пробілом; тепер такий текст відхиляється на вході (і це пояснено тестом).
3. Довга дія не вміщалась у 100×80 — схема збільшується; підписи умов «відлітали» від ліній через масштаб — тепер зсув від лінії зберігається.
4. У `.drawio` підпис початкової події був одним довгим рядком на заголовку доріжки — тепер переноситься.
5. Мій перший знімок великого процесу був порожнім — помилка скрипта знімків, не схеми.

## 4. Що не працює / не перевірено
- **Windows не перевірялось** (усе — Linux). Тести й переглядач не використовують нічого Linux-специфічного, але тест порівняння з Python пропускається без `python3`; на Windows без Python він **пропуститься** (це видно в підсумку тестів, не «успіх»).
- **`.drawio` не відкривалось у самому застосунку draw.io** (десктоп/онлайн): CDN заблоковано; перевірено лише в офіційному `viewer-static` (той самий рушій, але не повний редактор). Вигляд у вашому draw.io може трохи відрізнятися.
- Шрифти: розміри підписів виміряно з Arial/Liberation Sans і DejaVu Sans у Chromium на Linux; на Windows реально відрендерено не було.
- Лише `bpmn-auto-layout@2.0.0-alpha.2` (alpha); один пул; процеси до 120 кроків. Дуже великі процеси виходять широкими (розкладка по колонках) — читаються зумом, а не одним екраном.
- **Непідтримувану нотацію генератор не вміє виявляти сам:** у змісті AS-IS немає структурних позначок «паралельно/таймер/…», тож у 3a їх задають лише тестові пакети. Автоматично (наближено) їх виявлятиме агент 2 (3b); структурне поле в схемі AS-IS — окреме рішення (D53).
- Назва пулу = назва кейсу, не входить у хеш версії (D49).
- Структурні поля «результат», «умова входу», «вхідний артефакт», «джерела» на схемі не показуються (показано як відоме обмеження).
- Інтеграції з продуктом, смислової перевірки (агент 2), кнопки/сторінки схеми — **немає за задумом** (3b).
- Рішення D49–D59 **запропоновані**, не погоджені; лишається погодження власницею.
