## 1. Що саме вимагає рубрика (стисло)
Приймається, якщо: **(1)** є проєкт, що працює; **(2)** названо практики; **(3)** кожна названа практика має доказ — файл, коміт, тест, прогін, запис; **(4)** є відео 1–2 хв і в PR сказано, **що вирішувала людина, а що агент**. Кількість практик і обсяг коду не оцінюються. Повертають: практики без доказів; опис «усе гладко» заднім числом; не видно рішень людини; відео довше 2 хв чи без розповіді про агентну розробку. Шаблон PR: ім'я (справжнє, піде в сертифікат), проєкт і де код, посилання на відео, практики з доказами, інструменти й MCP, «що вирішувала я, а що агент», перевірка (команда й вивід).

## 2. Які практики заявляємо — і які ні
| Практика | Заявляємо? | Чому |
|---|---|---|
| Контекст-інженерія | **так** | є правила, інструкції агентів, передача контексту між сесіями; є місця, де правило спрацювало |
| Верифікація | **так** | 439 тестів, мутаційні перевірки, evals-критерії; є відтворений «червоний → зелений» |
| maker ≠ checker | **так** | є рев'ю окремим проходом із знайденими дефектами й виправленнями |
| Специфікації наперед | **так** | специфікація й план у git раніше за код; є місця, де специфікацію змінила реальність |
| Цикли (loop engineering) | **ні** | немає відтворюваного циклу «агент ганяється до зеленого» із записом запуску; описувати словами не будемо |
| Hooks, CI, Project Factory, журнал автономності | **ні** | не застосовано (hooks не активні, `.github/` немає); додавати заради кількості не будемо, рубрика цього не вимагає |

## 5. Чого ще бракує
1. **Відео 1–2 хв** — не знято. Має показати продукт і розповісти, як будувалось агентно. Показувати можна без API (зріз 1–2 у деморежимі з позначкою, `docs/bpmn-3a/index.html`, шлюз 3b-1 тестами) — але чесно називати, що модель не викликалась.
2. **PR у форк capstone-репозиторію** — не створено (і не створюємо без прохання). Потрібне **справжнє ім'я** (заповнює власниця) і посилання на відео. Код можна лишити в `arborfam/cx-process-agents1`, у форку — короткий `README.md` із посиланням (дозволено README).
3. **Перед PR перевірити доступ:** чи відкривається репозиторій рецензентам (видимість), і що в ньому немає реальних кейсів чи секретів (правило CLAUDE.md «не публікуй кейси»; джерела з позначкою «реальні» моделі не надсилаються). Це рішення власниці.
4. **Справжній запуск моделі й оцінка за evals** — немає (доступ API не відновлено). Без цього не заявляти якість AI.
5. **3b-2…3b-7** не реалізовано: у продукті ще немає шляху «погоджений AS-IS → BPMN».
6. **Автор зовнішніх перевірок зрізів 1–3a** не зафіксований у репозиторії (див. §3) — уточнити.
7. Підсумковий документ і наскрізна перевірка (зріз 4); Windows не перевірявся; рішення D49–D60 і D64 запропоновані, ще не погоджені.
8. Опис для PR треба писати з цього файлу й журналу комітів, **не прикрашаючи**: у ньому мають лишитись рецензентські знахідки, помилки агента й обмеження.
