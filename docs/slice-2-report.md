# Звіт: зріз 2 — справжній агент 1 (01.10.2026)

**Головне:** усе, що можна було зробити без моделі, зроблено й перевірено. **Жодного платного виклику не виконано, ключ не запитувався.** Справжню якість агента ще не перевірено.

## 1. Що реалізовано
- **Модельний шар** (`src/ai/`): клієнт Anthropic (офіційний SDK, лише сервер), перевірка відповіді до збереження, цитати, бюджет і ліміти, редагування ключів, журнал запуску. Деталі й причини — `docs/decisions.md` D35–D44.
- **Режим real:** стартує лише з повною конфігурацією (ключ, модель, бюджет); інакше відмова зі списком; на демо мовчки не перемикається. Кнопка «Оновити аналіз (AI)» у деморежимі вимкнена **з видимим поясненням**.
- **Запуски:** асинхронні, один активний на кейс, одна автоматична повторна спроба (тимчасовий збій або відповідь, що не пройшла перевірку), помилка не змінює версію/погодження/стан, застарілий результат — лише пропозиція, «застряглі» запуски відновлюються при старті.
- **Сценарії:** два окремі кейси «Підготовка CX до продуктових змін» (А — позитивний, Б — негативний), п’ять етапів, явне уточнення для Б. Оригінал пакета без змін (SHA-256 `9c22fa19…1077`), джерела SRC-00…09 із походженням (`scenarios/cx-preparation/`).
- **Критерії оцінки** (`evals/cx-preparation/criteria.md` + `criteria.ts`): по кожному етапу — очікувані факти, допустимі невизначеності, заборонені домисли, спосіб перевірки; програмні сигнали окремо від людських пунктів.
- **Інструкція агента** `prompts/analyst.md` v0.2 (runtime-блок із версією й хешем у журналі). Hooks **не активовано** і не перевірялись.
- **Картка:** прибрано пояснення «окремих полів немає…»; питання й невизначений перехід — одна прогалина з наслідками для кроків (програмні перевірки лишились окремо); банер/чипи показують справжню модель, коли вона підключена; панель сценарію.
- **Міграція баз:** нові колонки додаються до наявних даних; кейси, версії, погодження збережено (тест на старій схемі).

## 2. Що фактично перевірено
- `npm test`: **97 із 97** (було 54; +43). `tsc --noEmit` чистий.
- Нові перевірки: конфігурація й ліміти; редагування ключів; цитати; порушення відповіді (джерело не існує, вигадана цитата, «підтверджено агентом», видалення елементів, дублі ID…); повтор після невалідної відповіді; помилки різних видів без зміни версії; бюджет/запуски на кейс і добу/обсяг до виклику; параметри запиту до API (на підставному SDK, без мережі); класифікація помилок API; поетапне подання, ізоляція сценаріїв, «агент бачить лише додані джерела», **відсутність відбитків прихованої відповіді** в джерелах, версіях, запусках, журналі, картці, коді й інструкції негативного кейсу (і контроль чутливості в позитивному); негативний сценарій: невизначена гілка блокує погодження й BPMN, після явного уточнення — нова версія, яку треба прийняти й погодити; перевіряльник критеріїв на синтетичних «хороших/поганих» відповідях; міграція; HTTP-потік аналізу.
- Мутаційна перевірка: 6 навмисних поломок (цитати, бюджет, добовий ліміт, облік токенів, захист реальних даних, блок наступного етапу) — **кожну виявили тести**.
- Браузер (Chromium): `scripts/walkthrough-scenario.ts` → знімки `docs/demo/17–21`. Там «агента» імітує **підставний клієнт, не AI**; це перевірка інтерфейсу.
- **Тестові відповіді моделі — підставні й доводять лише програмну логіку, не якість AI.**

## 3. Що не працює / не перевірено без моделі
- Жодної справжньої відповіді моделі не отримано: **якість аналізу, виконання інструкції, поведінку на пропусках — не перевірено.**
- Чи API прийме структурну схему без помилки «Schema is too complex» — не перевірити без виклику (локально схема в межах документованих обмежень: ~4 КБ, 2 необов’язкових поля, 3 union-типи, без minLength/maxLength). Запасний режим — `CX_OUTPUT_MODE=text_json`.
- Оцінка токенів/вартості — оцінка (1.8 симв./токен); фактичні дані з’являться в журналі після перших запусків.
- Підключення на Windows, `npm.cmd`, переносний Node — не перевірялись (`docs/model-setup.md`).
- Програмні критерії — евристики; вердикт про якість виставляє людина.
- Hooks не активні; агент 2 і зріз 3 не реалізовувались.

## 5. Орієнтовна вартість і бюджет
Вимір на нашому пакеті (вхід росте від ≈5,6 до ≈21 тис. токенів за 5 етапів; вихід разом із міркуваннями оцінено 9,5–15,5 тис. токенів на запуск):
- один сценарій (5 запусків): Opus 5.5 ≈ **$1.5**; Sonnet 5.5 ≈ $0.8; Fable 5.1 ≈ $3.8;
- найгірший випадок одного запуску Opus 5.5 (вихід до 32 тис. токенів) ≈ $0.73 — менше за ліміт на запуск $1.5;
- два сценарії + явне уточнення + запас на повтори й розбір помилок (до 2× ) ≈ $4–7.
**Запропонований бюджет — $10** загалом (`CX_BUDGET_USD_TOTAL=10`), $1.5 на запуск; додатково — ліміт витрат у Console.

## 6. Налаштування ключа
`docs/model-setup.md` (PowerShell, `Read-Host -AsSecureString`, змінні сесії, ліміт у Console, відклик при витоку). Ключ у чат не надсилайте.

## 7. Що потрібно від вас перед першим платним запуском
1. Погодити модель (D44) і бюджет. 2. Створити окремий ключ із лімітом витрат у Console. 3. Запустити за `docs/model-setup.md`. 4. Почати зі сценарію А, етап 1, і переглянути результат за критеріями до наступних етапів.
