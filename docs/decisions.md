# Журнал рішень

Формат: ID · статус · рішення · причина · наслідок / ціна · альтернатива · коли й як переглянути.

Статуси: **Запропоновано** (чекає погодження власниці) · **Погоджено** · **Відхилено** · **Замінено**. Змінювати статус може лише власниця продукту (або за її явною вказівкою). Повний контекст — docs/technical-plan.md.

Станом на 29.09.2026 **жодне рішення не погоджене.**

---

## D1 · Запропоновано · Один застосунок Node.js + TypeScript
- **Рішення:** сервер, правила, запуск агентів і перевірка BPMN — в одному проєкті на TypeScript.
- **Причина:** Node 22 є в середовищі; екосистема BPMN (bpmn-js, bpmn-moddle) найсильніша в JavaScript; схеми даних описуються один раз для API та перевірки відповідей моделі.
- **Ціна:** якщо підтримувати продукт будуть Python-фахівці, доведеться навчатися TypeScript.
- **Альтернатива:** Python + FastAPI (див. technical-plan §1).
- **Перегляд:** до початку зрізу 1.

## D2 · Запропоновано · Браузер — лише показ і введення; рішення приймає сервер
- **Причина:** інваріант CLAUDE.md — блокування BPMN у програмній логіці, а не в кнопці.
- **Наслідок:** кожна дія перевіряється на сервері незалежно від інтерфейсу.
- **Перевірка:** тест прямого запиту до backend без погодження (зріз 1).

## D3 · Запропоновано · Кейси зберігаються у файлі SQLite
- **Причина:** один файл, без окремого сервера БД, легко копіювати й видаляти; достатньо для одного користувача.
- **Ціна:** не підходить для багатьох одночасних користувачів.
- **Альтернатива:** Postgres — лише при багатокористувацькому хмарному розміщенні.
- **Перегляд:** якщо з’явиться потреба в спільній роботі кількох людей.

## D4 · Запропоновано · Моделі викликаються лише з сервера; BPMN-XML будує код, а не модель
- **Причина:** ключ не потрапляє в браузер; гарантується відповідність елементів схеми ID кроків і відсутність «зайвих» кроків; технічна перевірка детермінована.
- **Наслідок:** агент 2 повертає структуру (JSON) за схемою, а не XML.
- **Ціна:** потрібен власний генератор і розкладка; якість автоматичної розкладки не перевірена.
- **Перевірка:** зріз 3a на вручну підготованому пакеті.

## D5 · Запропоновано · Вбудований `node:sqlite` із тонким шаром доступу до даних
- **Причина:** немає нативної збірки; працює в Node 22 (перевірено в цій сесії).
- **Ризик:** Node позначає модуль як експериментальний.
- **Запобіжник:** усе спілкування з базою — через один модуль; заміна на `better-sqlite3` — невелика зміна.
- **Перегляд:** на зрізі 1, якщо з’являться нестабільність або попередження, що заважають.

## D6 · Запропоновано · Розміщення: спочатку локальний запуск; хостинг — лише за окремим рішенням
- **Причина:** cloud-сесія Claude Code — середовище розробки, тимчасове; інтерв’ю можуть бути конфіденційними; CLAUDE.md забороняє публікувати кейси без дозволу.
- **Варіант А (за замовчуванням):** запуск на комп’ютері власниці. **Варіант Б:** захищений хостинг із паролем — потребує явної згоди, бо дані потрапляють на сторонній сервер.
- **Потрібне від власниці:** вибір до кінця зрізу 2. Для зрізу 1 не потрібно.
- **Статус доступу:** нічого не опубліковано, хостинг не обрано.

## D7 · Запропоновано · Застосунок має власний API-ключ моделі; доступ Claude Code його не замінює
- **Причина:** Claude Code — засіб розробки; runtime-виклики продукту — окремий доступ з окремою оплатою.
- **Факт середовища:** `ANTHROPIC_API_KEY` не задано (перевірено 29.09.2026, значення не друкувались). Тому **справжні AI-виклики зараз недоступні.**
- **Правила:** ключ — лише змінна середовища/секрет; `.env` у `.gitignore`; ліміт витрат у консолі постачальника до першого запуску.
- **Потрібне від власниці:** створити ключ і ліміт перед зрізом 2; підтвердити, чи обираємо Anthropic API.
- **Не перевірено:** чи покриває ваша поточна підписка API-доступ.

## D8 · Запропоновано · Модель — параметр конфігурації, не «зашитий» вибір
- **Порядок:** обидва агенти спершу на моделі середнього класу; порівняти з потужнішою на двох контрольних кейсах; лишити найдешевшу, що проходить перевірки.
- **Причина:** вартість і якість невідомі до вимірювання (спец. §9, §11).
- **Не робити:** називати ціни чи ліміти з пам’яті — звірити з офіційною сторінкою перед запуском.

## D9 · Запропоновано · Деморежим і справжній режим розділені явною змінною; мовчазного переходу немає
- **Рішення:** `MODEL_MODE=demo|real`; у `demo` — постійна помітка «ДЕМОРЕЖИМ — не AI» на екрані, у версії, у журналі й у експортованому документі; у `real` без ключа застосунок не стартує.
- **Причина:** CLAUDE.md забороняє підміняти доступ до моделі демонстраційними відповідями без явної позначки.
- **Наслідок:** версія, створена в деморежимі, лишається позначеною назавжди.
- **Перевірка:** тест «real без ключа → помилка старту»; тест наявності позначки у версії та експорті.

## D10 · Запропоновано · Незмінні записи: змінення = нова версія
- **Рішення:** `source`, зміст `as_is_version`, `approval`, `audit_log` не оновлюються й не видаляються; це забезпечено і кодом, і тригерами SQLite.
- **Причина:** інваріанти «оновлення не знищує правки, історію та прийняті версії» й «погодження прив’язане до незмінної версії».
- **Тип твердження** (`source_fact` / `analyst_confirmed` / `hypothesis` / `improvement_proposal` / `unknown`) зберігається на кожному твердженні, щоб не втрачати походження.
- **Ціна:** база зростає; потрібне явне «замінена» замість видалення.

## D11 · Запропоновано · Стани кейсу за специфікацією; запуск агента — окремий технічний стан
- **Рішення:** Дослідження → На погодженні → AS-IS погоджено → BPMN на перевірці → Завершено; будь-яке нове джерело чи зміна змісту повертає до «Дослідження» й позначає погодження `superseded` (без видалення).
- **Прийняття робочої версії ≠ погодження AS-IS.**
- **Причина:** спец. §2. Помилка лише у схемі не змінює AS-IS: створюється новий артефакт.

## D12 · Запропоновано · Серверна перевірка `canStartBpmn` у транзакції; вхід агента 2 береться з бази за ID погодження
- **7 умов:** стан; чинне погодження людини; збіг хеша; версія найновіша; немає нових джерел; немає відкритих критичних питань; немає активного запуску.
- **Агент не має доступу до модуля погодження й не має інструментів із побічними діями; вбудовані у джерела команди — дані.**
- **Застарілі результати:** агент 1 — зберігається як пропозиція на застарілій основі; агент 2 — стан `stale`.
- **Обмеження, яке слід пам’ятати:** прототип однокористувацький; захист від помилок агента й обходу кнопки, а не від людини з доступом до бази.

## D13 · Запропоновано · Перший зріз підтримує вставлений текст, `.txt`, `.md`
- **Причина:** мінімум ризику помилок читання. `.docx`/`.pdf` — після перших реальних кейсів.
- **Наслідок:** непрочитаний файл має статус `error`, не вважається опрацьованим і блокує погодження.

## D14 · Запропоновано · Помилки не знищують прийняті версії й не просувають стан
- **Правила:** одна автоматична повторна спроба лише для тимчасових збоїв; змістову прогалину повторним запуском не «лікуємо»; без нескінченних циклів. Таблиця — technical-plan §8.
- **Числові ліміти** (час, обсяг, вартість, кількість запусків) — початкові припущення; фіксуються після вимірювання на зрізі 2.

## D15 · Запропоновано · Структура картки
- **Перший екран:** шапка (назва, версія, текстовий статус, режим) · суть · головні зміни · усі критичні блокери на екрані (не згортаються) · одна наступна дія із поясненням блокування.
- **Деталі й докази** — окремо; біля твердження — тип і перехід до точного фрагмента джерела.
- **Причина:** CLAUDE.md, спец. §3. **Перевірка:** оцінка людиною «за хвилину» на зрізі 4.

## D16 · Запропоновано · Чотири зрізи зі зупинкою після кожного
1. Каркас довіри без AI (збереження, версії, погодження, серверне блокування). 2. Справжній агент 1. 3. BPMN (3a без AI, 3b агент 2). 4. Наскрізні кейси й підсумковий документ.
- **Причина:** найдорожчі й найризикованіші частини (модель, BPMN) не починаються, доки не доведені правила.
- **Кількість агентів:** рівно два продуктові. Технічні перевірки — код. Семантичну перевірку цитат відкладено до доказаної потреби.

## D17 · Запропоновано · Hooks: жодного не активовано; кандидати з’являться після зрізу 1a
- **Причина:** docs/hooks-plan.md забороняє команди-пустишки; реальні команди (`npm test`, `npm run typecheck`) ще не існують.
- **Кандидати:** SessionStart (`npm ci`), PostToolUse для `prompts/**` і схем, CI на push; PreToolUse для теки очікувань — лише за окремою згодою.
- **Умова активації:** перевірка події, успішного випадку, відомого дефекту, тайм-ауту, відсутньої залежності й фактичного завантаження в новій cloud-сесії.
