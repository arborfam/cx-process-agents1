# Як безпечно підключити справжню модель (Windows, PowerShell, переносний Node.js)

**Не перевірено на Windows** (розробка велась у Linux). Не надсилайте ключ у чат, у Git чи в скриншоти. Поки ви не погодите модель і бюджет, залишайтесь у деморежимі.

## 1. До ключа
1. У [Anthropic Console](https://console.anthropic.com) створіть **окремий ключ лише для цього експерименту**.
2. У Console задайте **ліміт витрат** (spend limit) для цього ключа/робочої області, не більший за бюджет застосунку. Це другий, зовнішній захист.
3. Якщо ключ потрапив у чат, файл чи скриншот — одразу відкличте його в Console й створіть новий.

## 2. Запуск у PowerShell (ключ живе лише в цьому вікні)
Відкрийте PowerShell у папці проєкту й виконайте по черзі (шлях до Node змініть на свій):

```powershell
$env:Path = "C:\tools\node-v22.22.2-win-x64;" + $env:Path      # переносний Node.js
$k = Read-Host "Ключ API (символи не показуються)" -AsSecureString
$env:ANTHROPIC_API_KEY = [System.Net.NetworkCredential]::new("", $k).Password
$env:MODEL_MODE = "real"
$env:CX_MODEL = "claude-opus-5-5"          # модель обираєте ви; значення за замовчуванням немає
$env:CX_BUDGET_USD_TOTAL = "10"            # загальний бюджет застосунку, USD
npm.cmd start
```
`Read-Host -AsSecureString` не друкує ключ і не лишає його в історії команд. Змінна `$env:…` існує лише в цьому вікні; закрийте вікно — ключ зникне. Не вставляйте ключ прямо в команду.

Необов’язкові змінні (є розумні значення): `CX_EFFORT` (`medium`), `CX_MAX_OUTPUT_TOKENS` (32000), `CX_TIMEOUT_MS` (300000), `CX_MAX_INPUT_CHARS` (150000), `CX_BUDGET_USD_PER_RUN` (1.5), `CX_MAX_RUNS_PER_CASE` (12), `CX_MAX_RUNS_PER_DAY` (20), `CX_OUTPUT_MODE` (`structured`; `text_json` — запасний варіант, якщо API відхилить схему), `CX_OUTPUT_CONTRACT` (`delta`).

**`CX_OUTPUT_CONTRACT`** — що саме агент 1 повертає у відповіді (D80, `docs/agent1-delta-contract.md`):
- `delta` (за замовчуванням) — **лише нові й змінені елементи**; повний опис збирає застосунок і проганяє на ньому всі перевірки. Відповідь перестає залежати від обсягу накопиченого опису;
- `full` — повна оновлена версія щоразу (початковий контракт). Працює, доки опис невеликий: відповідь містить увесь опис, тому з часом упирається в `CX_MAX_OUTPUT_TOKENS`.

У вікні запуску видно рядок із чинним контрактом. Контракт кожного запуску записується в журнал (`run.output_contract`), тому старі запуски читаються як `full` — за ним вони й виконувались.

Якщо чогось бракує, застосунок **не стартує** і перелічує, чого саме (на демо мовчки не перемикається). У вікні запуску й угорі сторінки видно «РЕЖИМ СПРАВЖНЬОЇ МОДЕЛІ», назву моделі й залишок бюджету.

## 3. Альтернатива: файл `.env`
Застосунок `.env` **не читає**; якщо захочете цей спосіб, це окрема зміна. Файли `.env` уже виключені з Git (`.gitignore`), але ключ у файлі зберігається відкритим текстом, тому для цього прототипу рекомендовано змінні сесії, як вище.

## 4. Що надсилається моделі
Тексти джерел кейсу, поточна версія опису й інструкція агента (`prompts/analyst.md`, блок між маркерами). Джерела з позначкою «реальні» не надсилаються; використовуйте лише синтетичні матеріали. Критерії оцінки й приховане уточнення (до явної дії) моделі не передаються.

## 5. Після запусків
У «Історії → Запуски» видно модель, версію й хеш інструкції, тривалість, токени, вартість, спроби. Перевіряйте результат за `evals/cx-preparation/criteria.md`.
