# Тестові схеми зрізу 3a — як відкрити

**Усе тут створено без AI.** Вхідні пакети підготовлено вручну (синтетичні, не стосуються реальних процесів), схеми створено програмою без викликів моделі й перевірено зворотним читанням. Це перевірка генератора, а не якості аналізу агентів.

## Як відкрити (Windows, нічого встановлювати не треба)
1. Розпакуйте ZIP гілки `claude/peaceful-allen-f4yf0n` і відкрийте папку `docs\bpmn-3a`.
2. Двічі клацніть **`index.html`** → відкриється таблиця всіх пакетів: що кожен перевіряє, **очікуваний** результат (записаний у пакеті до запуску) і **фактичний**.
3. У рядку пакета натисніть **«переглядач»** — сторінка зі схемою (з водяним знаком bpmn.io в правому нижньому куті, його не вилучено), таблицею «крок AS-IS ↔ елемент схеми» (клацніть рядок — елемент підсвітиться) і відомими обмеженнями. Працює без інтернету.
4. **`.bpmn`** — основний результат: відкривається в Camunda Modeler, bpmn.io, draw.io (Файл → Відкрити). **`.drawio`** — експорт: відкривається в draw.io (diagrams.net).

## Що де лежить
| Тека | Вміст |
|---|---|
| `packages/` | **вхідні пакети** (JSON, читабельні): що перевіряє пакет, очікуваний результат, ролі, кроки, переходи |
| `schemes/` | для кожного коректного пакета: `.bpmn`, `.drawio`, `.map.json` (карта «крок ↔ елемент»), `.html` (переглядач) |
| `results/` | для відхилених пакетів: **пояснення відмови** (`blocked` / `unsupported`) — файлу схеми немає за задумом |
| `screenshots/` | знімки: `*-bpmn.png` — як `.bpmn` виглядає в bpmn-js; `*-drawio.png` — як `.drawio` виглядає в переглядачі draw.io |

## Пакети
| Пакет | Що показує | Результат |
|---|---|---|
| p01-sequence | лінійна послідовність, 2 доріжки | ok |
| p02-branch | розгалуження на 3 гілки, дві кінцеві події | ok |

## Як перестворити
`npm install`, потім `npm run bpmn:samples` (перестворює файли й індекс). Знімки потребують Chromium і (для `.drawio`) локального переглядача draw.io — без них скрипт їх пропустить і скаже про це. Тести: `npm test`.

## Чого це НЕ доводить
Технічна перевірка доводить лише, що схема **дослівно збігається з погодженим пакетом**. Вона не доводить, що сам опис правильно відображає реальний процес — це перевіряє людина за таблицею «крок ↔ елемент».
