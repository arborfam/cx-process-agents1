# Як експортувати один синтетичний кейс для розбору якості

Навіщо: щоб розбирати, що саме агент зробив на кожному етапі (версії, джерела, журнал спроб, вартість, порушення), а не лише скриншоти. **Усю базу надсилати не потрібно.**

## Що робить скрипт
- Лише **читає** базу (`PRAGMA query_only`), нічого не змінює й не мігрує.
- Експортує **один** кейс: джерела (текст), усі версії AS-IS із зазначенням, хто їх створив (агент чи ви), запуски агента (модель, версія й хеш інструкції, токени, вартість, кількість спроб, порушення, перевірки), журнал дій, погодження.
- **Не бачить** ключа API, коду доступу, змінних середовища, інших кейсів. Усі тексти додатково проходять через редагування ключів; якщо у файлі лишилось щось схоже на ключ, експорт скасовується і файл не створюється.
- **Відмовляє**, якщо в кейсі є джерела з позначкою «реальні» (рішення D18: реальні дані ніде не копіюються).

## Команди (PowerShell, у папці проєкту; Node.js у PATH — так само, як для запуску застосунку)
Застосунок можна не зупиняти.

1. Побачити кейси та їхні ID:
```powershell
node --import tsx scripts\export-case.ts --list
```
2. Експортувати потрібний (сценарій А — той, що з `claude-opus-5-5`):
```powershell
node --import tsx scripts\export-case.ts --case <ID_кейсу> --out export-scenario-a.json
```
Файл `export-scenario-a.json` з'явиться в тій самій папці. Якщо база лежить не в `data\cx.sqlite`, додайте `--db шлях\до\cx.sqlite`.

3. Перед відправленням можна відкрити файл у Блокноті й переконатися, що там лише вигадані матеріали сценарію. Надішліть файл у чат.

Скрипт перевірено тестами (`tests/export-case.test.ts`): лише читання, без ключів (у тому числі з журналу й змінної середовища), без чужих кейсів, відмова для «реальних» джерел. **На Windows не перевірявся.**
